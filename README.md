# ClassCal

一个**本机离线**的课表 App（Flutter / Android）。从教务系统导出的 `.ics` 导入课表，
画周网格，并且在上课前提醒你 —— 提醒由系统闹钟触发，App 不用一直开着。

没有账号，没有服务器，没有网络请求。

## 功能

**课表**

- 导入教务系统的 `.ics`（自写解析器，处理 75 字节折行、`TZID`、连堂课跨大节）
- 多个日程并存，各是一个标签页；另有「总览」把所有日程按**日期**合并显示
- 单次事件（调课 / 补课）、整份课表的整体平移、整门课的删除与改色
- 导出 `.ics` / JSON 备份
- 主题跟随系统壁纸取色，也可自选颜色；深色 / 浅色

**课前提醒**（Android）

- 提前量三层解析：**单课 → 日程 → 全局**，就近优先
- **定位门控**三态：照常提醒 / 已经在教室附近就不弹 / 照弹但不出声
- 通知会自动清除，省得上午的提醒堆到晚上还挂在通知栏
- **重复提醒到教室**：没到教室就隔一段时间再弹一次，带「我已到教室」按钮，
  到教室或上课那一刻自己停

**桌面小组件**

- 一个可自由缩放的实例（2×1 到 280×460dp），内容按尺寸自适应
- **过了零点自己翻页**，不用进 App；点卡片（齿轮除外）打开 App，落到那个实例
  配的日程 + 今天那一周
- 显示什么由**每个实例单独选**：下一节 / 今日 / 今日+明日 / 本周缩略网格
- 每个实例可选「跟随当前日程」或固定某一个日程，可显示或隐藏日程名
- 网格里画**缩写**（预置一套 + 可逐门自定义）—— 一列只有屏宽的七分之一，
  全称一定会被截成「高等数…」

## 架构

**Dart 决定「什么时候、提醒什么、要不要门控」，Kotlin 负责排 `AlarmManager` 闹钟、
到点时探一次位置、发通知、画小组件位图。**

这条分工是刻意的：门控要能在 App 已经死掉时判断，所以它不能待在 Dart 里。
代价是所有跨端的东西都必须过一遍 JSON 快照，好处是**加一种门控处理方式只改 Dart**，
不用动 Kotlin。也因此没用 `flutter_local_notifications` / `geolocator`。

- 课表存在 `drift`（SQLite）里，设置存在 `settings.json` 里。**设置不加数据库列** ——
  加一列要 `schemaVersion` 和迁移，而设置项本来就是「一个 JSON 对象」，加字段零成本。
- 三层设置（全局 / 日程 / 单课）只有一份解析实现：`ReminderScope` 是那个读写目标，
  所以四个设置节（提前量 / 门控 / 自动清除 / 重复）不用抄两遍。
- 提醒表的推送是**监听数据本身**的副作用，而不是让七八个编辑入口各自调一遍 ——
  漏一个的表现是「改了课表但提醒还按老时间响」，极难发现。

```
lib/
  app/           provider 接线、原生同步宿主
  core/          纯逻辑：时间、提醒计划、主题、缩写、跨端快照
  data/          drift 表、仓库、ICS 导入导出
  features/      界面（首页周网格、设置各页、小组件配置）
android/app/src/main/kotlin/…
                闹钟、通知、定位、小组件渲染与存储
test/            345 条
tool/            开发期核对脚本
```

## 构建

需要 Flutter 3.x（Dart SDK `^3.13.5`）和 Android SDK（Java 17）。

```bash
flutter pub get
flutter build apk --release --target-platform android-arm64
```

**要带 `--target-platform android-arm64`。** 不带的话打出来是一个通用包，
里面同时装着三种 CPU 架构的原生库：实测 64,815,693 字节，其中 64,101,604
（98.9%）是三份 `.so`，而一台手机**只需要其中一份**。只出 arm64 之后实测
22,524,634 字节（21.5 MB）—— 省掉 65%，那 40 多 MB 是纯粹白带的。

（新包里仍残留两个几十 KB 的 `libdartjni.so`（armeabi-v7a / x86_64），
是 `dartjni` 这个包给每种架构都塞了一份小桩，合计约 190 KB、不到 1%。
为它去配 `packagingOptions` 排除，收益比坑小，不做。）

如果要用 x86_64 模拟器调试，就**别加这个参数**（或者用 `flutter run`，
它自己按目标架构构建），否则装不上、报错还看不懂。

release 包目前**用的是 debug 签名**（`android/app/build.gradle.kts` 里那行
`signingConfig = signingConfigs.getByName("debug")`），profile 同理 ——
所以三种包能互相覆盖安装而不丢数据。真要发布请换掉这个签名配置。

一个可以再省几个百分点、但**故意没做**的选项是 `--obfuscate`：它会让
`libapp.so` 小一点，代价是崩溃栈变成一串不可读的符号。为 1 MB 换掉排查能力
不划算。

## 测试

```bash
flutter analyze     # 零警告
flutter test
```

`test/fixtures/timetable_2026-2027-1.ics` **不在仓库里**（那是真实课表，带真实教室和
老师姓名）。缺这个文件时「拿真实课表验一遍」那一组会**整组跳过**而不是失败 ——
本地想跑它就自己导一份放回那个路径，见 [test/fixtures/README.md](test/fixtures/README.md)。

提醒和小组件这两块有**契约测试**：直接读 `android/app/src/main/kotlin/` 下的
`ReminderBridge.kt` 等文件，核对待两侧的通道名与动作常量。这类字符串对不上时
两端都不报错，只会「什么都没发生」，所以值得专门钉住。

## 隐私

- **没有任何网络代码**，课表和设置只在本机。
- 权限只用在该用的地方：`SCHEDULE_EXACT_ALARM`（准点响）、
  `ACCESS_BACKGROUND_LOCATION`（App 已死时判断你在不在教室，只在提醒响的那一刻探一次）、
  `POST_NOTIFICATIONS`。
- 定位结果不落盘、不上传，只用来做一次「在不在教室附近」的布尔判断。
- 门控**只在课程地点能对上一个你手动记录的地点时才生效**；对不上就照常提醒 ——
  漏一次提醒的代价比多响一次大得多。
